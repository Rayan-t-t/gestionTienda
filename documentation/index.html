Gestor de videojuegos

Aplicación Ionic + Angular standalone para gestionar el catálogo de una tienda de videojuegos. Proyecto de Desarrollo de Interfaces (DAM).

Stack

  • Ionic con Angular standalone y TypeScript estricto.
  • Angular Signals, componentes OnPush y rutas lazy.
  • Supabase Auth REST y PostgREST para autenticación y catálogo.
  • Firebase Firestore para auditoría de actividad.
  • Vitest mediante el runner integrado en Angular CLI.
  • Compodoc para documentación técnica.
  • Vercel para el despliegue de la SPA.

Requisitos

  • Node.js 22 o superior y npm.
  • Un proyecto Supabase y un proyecto Firebase configurados.

Instalación y configuración

Example :
npm ci
Copy-Item src/environments/environment.example.ts src/environments/environment.ts

Completa src/environments/environment.ts con la URL y la clave anon/public de Supabase y la configuración de Firebase. El archivo está ignorado por Git; no añadas claves service_role, secretos ni credenciales privadas al cliente.

Para generar el archivo desde variables de entorno, define:

  • SUPABASE_URL
  • SUPABASE_ANON_KEY
  • FIREBASE_API_KEY
  • FIREBASE_AUTH_DOMAIN
  • FIREBASE_PROJECT_ID
  • FIREBASE_STORAGE_BUCKET
  • FIREBASE_MESSAGING_SENDER_ID
  • FIREBASE_APP_ID

npm run build genera environment.ts antes del build. Si ya existe un archivo local y no se han definido variables, el script lo conserva. Si se configura alguna variable, deben estar definidas todas para generar un archivo completo. En GitHub Actions se usan valores de ejemplo; en Vercel configura los valores reales como variables de entorno del proyecto.

Base de datos Supabase

El siguiente SQL crea la tabla public.video-juegos, habilita RLS y concede lectura a usuarios autenticados y escritura únicamente a administradores. Ejecútalo en el SQL Editor de Supabase sobre un proyecto nuevo. Si ya existe la tabla, revisa y adapta las columnas/constraints antes de aplicar los grants y políticas.

Example :
create table if not exists public."video-juegos" (
  id integer generated by default as identity primary key,
  created_at timestamptz not null default now(),
  titulo text not null,
  codigo_sku text not null unique,
  descripcion text,
  precio numeric(10, 2) not null default 0 check (precio >= 0),
  stock integer not null default 0 check (stock >= 0),
  valoracion numeric(3, 1) check (valoracion between 0 and 10),
  fecha_lanzamiento date,
  disponible boolean not null default true,
  plataforma text not null check (plataforma in ('PC', 'PS5', 'Xbox', 'Switch')),
  genero text not null check (genero in ('RPG', 'Accion', 'Deportes', 'Estrategia', 'Aventura')),
  etiquetas text[] not null default '{}',
  requisitos jsonb not null default '{}'::jsonb,
  portada_url text
);

alter table public."video-juegos" enable row level security;
revoke all on table public."video-juegos" from anon, authenticated;
grant select, insert, update, delete on table public."video-juegos" to authenticated;

create policy "Usuarios autenticados pueden consultar videojuegos"
on public."video-juegos"
for select to authenticated
using (true);

create policy "Solo administradores pueden crear videojuegos"
on public."video-juegos"
for insert to authenticated
with check ((select auth.jwt() -> 'app_metadata' ->> 'role') = 'admin');

create policy "Solo administradores pueden actualizar videojuegos"
on public."video-juegos"
for update to authenticated
using ((select auth.jwt() -> 'app_metadata' ->> 'role') = 'admin')
with check ((select auth.jwt() -> 'app_metadata' ->> 'role') = 'admin');

create policy "Solo administradores pueden eliminar videojuegos"
on public."video-juegos"
for delete to authenticated
using ((select auth.jwt() -> 'app_metadata' ->> 'role') = 'admin');

Las políticas RLS aplican también cuando se llama directamente al Data API; ocultar botones o proteger rutas en Angular no sustituye esta autorización. Revisa además los grants efectivos y que public esté expuesto al Data API. La clave service_role omite RLS y nunca debe incluirse en la aplicación.

Promocionar un usuario a administrador

En un entorno administrativo confiable, actualiza app_metadata del usuario (no user_metadata, que puede modificar el propio usuario). Por ejemplo, desde el SQL Editor:

Example :
update auth.users
set raw_app_meta_data =
  coalesce(raw_app_meta_data, '{}'::jsonb) || '{"role":"admin"}'::jsonb
where email = 'admin@example.com';

Verifica que se haya actualizado exactamente una cuenta. El usuario debe volver a iniciar sesión o renovar el token para recibir el claim actualizado. No ejecutes esta operación desde el frontend.

CI y flujo Git

GitHub Actions ejecuta npm ci, lint, tests, build de producción y Compodoc en cada push o pull request dirigido a develop o main. El flujo no despliega: Vercel ejecuta el comando de build configurado y no genera una salida desplegable si fallan los tests, el lint o el build.

Trabaja en ramas feature/*, abre pull requests a develop y fusiona con --no-ff. La rama main contiene las entregas estables.

Despliegue en Vercel

  1. Importa el repositorio desde el panel de Vercel y selecciona el framework Other.
  2. Deja vercel.json como configuración: ejecuta tests, lint, build y documentación; publica www/ y aplica rewrite SPA a index.html.
  3. En Settings → Environment Variables, añade los ocho valores listados en Instalación y configuración para Production, Preview y Development según corresponda.
  4. Conecta main como rama de producción; las demás ramas pueden generar previews. Vercel no podrá completar un build si falla la etapa de tests.

La URL de Supabase y las claves anon/public de Supabase y Firebase son configuración pública del cliente; la seguridad debe descansar en RLS y las reglas de Firestore, nunca en ocultar los valores ni incluir claves administrativas.

Credenciales de prueba

No se incluyen cuentas reales ni contraseñas en el repositorio. Para probar, crea un usuario de Supabase Auth, por ejemplo usuario-prueba@example.test, con la contraseña local <CONTRASEÑA_DE_PRUEBA>. Asigna app_metadata.role = 'user' o admin desde un entorno confiable para verificar ambos permisos.
